# Рендер шва после перехода на Aeronautics

Этот документ описывает 0.4.4. Снимки и копии из 0.2/0.3 сохранены в истории Git,
но не являются текущим рендерным путём.

## Канонические данные и несколько видов

Сервер создаёт через API Aeronautics две глобальные плоскости с параллельным
преобразованием X на ±полный оборот. Зависимость заранее загружает настоящие
канонические чанки другой стороны в свой разреженный клиентский кэш. Нативный
рендер порталов показывает их из преобразованной камеры с отсечением по плоскости.
Сущности идут через обычный трекер форка и получают стандартные обновления.

При переходе в том же измерении поддерживается тот же клиентский мир. В проверке
сохраняются `ClientLevel`, `LevelRenderer` и объект исходного чанка, который уже
наблюдался через портал. Отдельных around_planet image-chunks и вторичного
entity cache больше нет. Готовность соседей, свет, clipping, прозрачность и
контексты Sodium — ответственность зависимости.

## Что остаётся в around_planet

- Конфигурация двух плоскостей, высоты и охвата Z, безопасное согласование только
  своих тегов при старте/отключении.
- Фильтр обычных наблюдений источников за X-границей. Одна колонка снаружи оставлена
  для точек назначения и готовности соседей; приватные области Sable разрешены.
- Короткая дистанция despawn через шов, без подмены координат игрока.
- Маска внешних колонок Cruising, каноническая генерация DH и точное фрагментное отсечение его LOD.
- Второй DH render tree с предзагрузкой и сменой ролей при EW-переходе, без потери готового набора.
- Защита пассажиров Sable до подключения переноса корпуса через глобальную пару.
- Совместимое исправление ошибочного закрытия глобального хранилища на каждом тике.

Генерация и сохранённые координаты чанков не перенаправляются. Явные сторонние
загрузки и служебный halo генератора сохраняются. Внешние сохранённые чанки
или записи DH не удаляются. DH 3.3.3 рисует подготовленную геометрию внутри нашего
портала без полноэкранных fog/SSAO/AA-проходов; готовые GPU-буферы и идентичность
деревьев при переходе/возврате проверяются клиентским harness. Детали и ограничения:
[dh-portals.md](dh-portals.md). Биомный дальний вид Cruising отдельно не перенесён.

Форк также содержит обычные взаимодействия через портал; специальные протоколы
конкретных модов и физические корабли требуют отдельных сценариев. Физический
корабль через управляемый глобальный шов на этой стадии не поддерживается.
