# Освещение Blender-модели и внутренняя облицовка — alpha.54

Подтянут пользовательский коммит `6a238e0` с новой моделью. Его OBJ и MTL сохранены побайтно.

Причина свечения всего двигателя: Blender записал `Ka 1 1 1` для материалов, а штатный OBJ-загрузчик NeoForge при включённом `emissive_ambient` превращает Ka в полную яркость и отключает направленное затенение. В JSON модели задано `emissive_ambient: false`; `shade_quads: true` сохранено. Теперь Ka при очередном экспорте из Blender не включает свечение внешних поверхностей.

Причина тёмных внутренних сегментов: активная облицовка строилась по прежним массивам высот и радиусов. Они больше не используются. Клиент при загрузке ресурсов читает грани материала `inner` непосредственно из того же OBJ: сейчас это 32 панели и крышка камеры, всего 33 грани. Свечение смещается на малую величину вдоль нормали каждой реальной грани, чтобы исключить наложение с тёмной поверхностью. Внутренняя часть остаётся полнояркой только во время фактического горения топлива.

При дальнейших изменениях достаточно сохранить имя материала `inner` для поверхностей, которые должны светиться. Облицовка и положение/ширина струи обновятся при перезагрузке ресурсов; старые Java-массивы профиля больше не нужны. Чтение OBJ выполняется один раз на перезагрузку, а не каждый кадр. Исторический генератор модели защищён от случайного запуска поверх ручных правок: теперь для его запуска требуется явный `--replace-model`.

Проверки: клиент с Create/Pondus/Sable/Cruising/DH/Simple Clouds загрузил все 33 грани; работающая и выключенная модель осмотрены снизу. Добавлены проверки реального пользовательского OBJ, изменённых сегментов, отрицательных индексов, экспортированных ссылок v/vt/vn, треугольников и перемещённого выхода сопла.
