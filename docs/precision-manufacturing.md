# Точное производство — alpha.75

Три станка работают от FE. Меню открывается пустой рукой; предметы и энергия передаются стандартными capability NeoForge. Вход: сверху и сбоку, выход: снизу. Без указания стороны доступны оба слота. Ёмкость — 200 000 FE, приём — до 20 000 FE за обращение. Станки сохраняют работу при выгрузке, но не производят предметы в выгруженном чанке. На корабле их загружает игрок или загрузчик физических конструкций.

| Станок | Детали | Вход на одну деталь | Время | Энергия |
| --- | --- | --- | --- | --- |
| Токарный | Точная шестерня, сопло Лаваля | 1 блок металла | 8 с | 60 FE/тик |
| Фрезерный | Высокоточный корпус, крыльчатка | 1 блок металла | 9 с | 60 FE/тик |
| 3D-принтер | Все четыре | 4 пыли металла | 15 с | 100 FE/тик |

В орбитальном пространстве время и суммарный расход FE меньше на 25%. Бонус не зависит от высоты служебного участка: проверяется принадлежность физической позиции космической области, с преобразованием координат Sable. На поверхности Луны обычное время; происхождение детали отмечается отдельно (`moon`). Предварительные изделия и расход энергии не появляются при недостаточном входе или занятом выходе. Смена материала, выбранной детали, рецепта или среды сбрасывает незаконченную работу; выгрузка/загрузка сохраняет её.

Станки первого уровня собираются в верстаке из обычных материалов. Принтер требует уже изготовленные детали и собирается в механическом крафтере Create. Пыль получается на мельнице Create: один слиток → одна пыль. Таким образом, принтер расходует четыре слитка вместо девяти в металлическом блоке. Начальная производственная цепочка не требует принтера.

## Материалы

| Материал | Износостойкость | Температура, °C | Массовая нагрузка | Коррозионная стойкость |
| --- | --- | --- | --- | --- |
| Медь | 0,30 | 600 | 0,40 | 0,75 |
| Железо | 0,65 | 1200 | 0,70 | 0,35 |
| Цинк | 0,20 | 300 | 0,30 | 0,65 |
| Незерит | 0,95 | 2400 | 0,95 | 0,95 |

Это стартовые игровые характеристики. Три коэффициента находятся в диапазоне 0–1; температура — 0–100 000 °C. Больше означает лучше. Сложные рецепты проверяют все заданные нижние границы; превышение одной характеристики не компенсирует нехватку другой.

Деталь хранит снимок свойств материала, его идентификатор, цвет и место изготовления. Изменение датапака влияет на новые детали. Старые детали сохраняют исходные свойства. Незавершённые предметы без компонента не подходят к рецептам. Эти характеристики сейчас выбирают допустимые компоненты для сборки; отдельной симуляции износа и изменения тяги собранного двигателя пока нет.

Pondus продолжает рассчитывать массу штатным способом: собственные поправки к массе/центру масс не добавлены.

## Свой материал через датапак

Файл `data/my_pack/manufacturing_materials/titanium.json`:

```json
{
  "block": {"tag": "c:storage_blocks/titanium"},
  "dust": {"tag": "c:dusts/titanium"},
  "stats": {
    "wear_resistance": 0.8,
    "working_temperature": 1700,
    "load_capacity": 0.8,
    "corrosion_resistance": 0.9
  },
  "color": 12369084,
  "priority": 0
}
```

Идентификатор материала — `my_pack:titanium`. `block` и `dust` — обычные ингредиенты NeoForge; можно указать конкретный `item`. Требуется мод, предоставляющий соответствующие предметы, или заполненные теги. `color` — десятичный RGB (0–16777215), без альфы; стандартный цвет 13421772. Больший `priority` побеждает при совпадении входных ингредиентов; затем сортировка по идентификатору. Для перевода имени можно добавить ключ `material.my_pack.titanium` в клиентский ресурс-пак.

Стандартные металлы используют `c:storage_blocks/<material>` и `c:dusts/<material>`. Цинковый блок предоставляется Create. Наши четыре пыли зарегистрированы собственным модом. Крафты Create имеют условие присутствия Create; загрузка самого мода не делает Create обязательной зависимостью.

## Ингредиенты по характеристикам

В `key` рецепта `create:mechanical_crafting`:

```json
{
  "type": "around_planet:qualified_part",
  "part": "laval_nozzle",
  "minimum": {
    "working_temperature": 900,
    "load_capacity": 0.5
  },
  "environment": "any"
}
```

Незаданные минимумы равны нулю. `environment`: `any`, `ground`, `moon`, `orbit`. Допустимые детали: `precision_gear`, `laval_nozzle`, `impeller`, `precision_housing`. Такой ингредиент учитывает компоненты конкретного стека, в том числе при передаче рецептов клиенту. Обычный верстак не может выполнить рецепт механического крафтера.

На детали переведены рецепты жидкостного двигателя, твердотопливного сопла, RSU, распределителя, гасителя инерции, датчика, планера, телескопа и загрузчика. Базовые колонки и твёрдое топливо остаются простыми рецептами.

## Рецепты станков

Файл в `data/<namespace>/recipe/`:

```json
{
  "type": "around_planet:machining",
  "machine": "lathe",
  "part": "laval_nozzle",
  "input_count": 1,
  "output_count": 1,
  "processing_ticks": 160,
  "orbital_processing_ticks": 120,
  "energy_per_tick": 60,
  "environment": "any"
}
```

`machine`: `lathe`, `mill`, `printer`. Токарный/фрезерный сохраняют специализацию даже для пользовательских рецептов. Вход определяется выбранным материалом: блок для обычных станков, пыль для принтера. `output_count` по умолчанию 1; `environment` по умолчанию `any`; отсутствие/ноль `orbital_processing_ticks` отключает орбитальный бонус данного рецепта. Время — 1–72 000 тиков, энергия — 1–200 000 FE/тик, количество — 1–64. Чтобы изменить стандартный рецепт, переопределите его идентификатор в датапаке. При нескольких подходящих рецептах используется первый по идентификатору; не создавайте неоднозначные альтернативы, вместо этого переопределяйте стандартные рецепты для нужного окружения.

Лунные и орбитальные компоненты уже можно требовать через `environment`. Новых технологий, потребляющих такие детали, этот этап ещё не добавляет.

## Проверки

Alpha.75: 250 модульных проверок, 100 серверных регрессионных тестов с Create/Sable/Pondus/Deep Seas/Cruising. Отдельно проверены автономный сервер без необязательных модов и настоящий клиент: три меню, смена изделия, передача характеристик результата, защита предварительного просмотра от извлечения и синхронизация FE выше 65 535. Тестовый дополнительный материал и классы тестов не входят в выпускаемый JAR.
