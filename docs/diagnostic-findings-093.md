# Выводы по диагностике и изменения 0.9.3

В пользовательском тесте 0.9.2 записаны 90 серверных и 91 клиентская сводки.
Ниже агрегаты, без исходного лога, имён и маршрута игрока.

## Что подтверждено

- 8 переходов соответствуют 8 перестановкам деревьев DH. Дополнительное дерево
  создано один раз; сброс в конце сеанса совпадает с выходом из мира. Нет
  свидетельств пересоздания деревьев на каждом переходе.
- 7694 обычных chunk-пакета отправлены и столько же приняты. Для снимков тоже
  совпадает общий объём переданных и принятых данных. Счётчик блокировки
  отправки из-за неподтверждённых batch не появлялся. Пересылка не выглядит
  основной причиной наблюдавшихся пропаданий.
- 1802 меша вытеснены по возрасту, ещё 387 — по лимиту. В старом коде время
  жизни обновлялось доступностью исходных данных, но не фактом рисования.
  После перехода исходная колонка закономерно выходит из native cache;
  отрисовываемая геометрия могла истечь через десять секунд.
- Кэш удерживал и результаты с пустыми слоями. Само наличие записи раньше
  считалось покрытием для маски DH, хотя рисовать в ней было нечего.
- Дополнительная маска DH занимала в среднем около 1.3 мс на каждый проход
  на машине пользователя. Один и тот же объём вычислялся для непрозрачного
  и прозрачного проходов.

## Что пока не установлено

DH имел очередь в десятки тысяч чанков уже вдали от шва, когда дополнительный
вид around_planet не работал. План — `SURFACE_THEN_CHUNKS`, режим — `FEATURES`.
За тест завершились 332 задачи, 988 отменены (372 отмены отмечены нашим внешним
ограничением). Часть отмен приходится на закрытие мира. Время запроса включает очередь, поэтому средние 86 секунд
нельзя трактовать как стоимость генерации одного чанка. Серверный тик в пике
превысил 10 секунд. По одним агрегатам нельзя указать мод или функцию, которая
задержала этот тик. Политика скорости Cruising была неактивна, detail floor 0;
гипотеза о вызванном телепортацией грубом режиме в этом тесте не подтвердилась.

## Исправления

1. Обновлять срок удержания видимых периодических размещений и реально
   рисуемых мешей. Выйдя из окна обзора, меши по-прежнему истекают.
2. Исключать пустые компиляции из покрытия DH. Не заменять ими прежний
   непустой меш с теми же блоковыми данными. Освобождать пустые VBO.
3. Предзахватывать полосу по дальности обзора, до трёх колонок за тик,
   пропуская native секции без подтверждённой геометрии. Ограниченный один
   compile/upload job сохраняется.
4. Настраиваемые пределы по умолчанию: 128 MiB / 1536 секций; сначала
   вытесняются размещения вне окна, затем реже рисуемые. Это увеличивает
   прежний лимит, но не превращает кэш в неограниченное хранение чанков.
5. Переиспользовать одну маску DH в пределах кадра при совпадающих мире,
   секции камеры, сдвиге и размерах; обновлять позиционные uniforms в обоих
   проходах. Повторная загрузка 3D-текстуры не требуется.
6. Для оставшихся пауз — ограниченное `server.slow_tick`: стек активного
   серверного тика старше 500 мс, максимум одна выборка за пять секунд.

Обычный watch/cache Minecraft при переносе всё ещё меняет область. Этот патч
удерживает визуальную геометрию на время перехода; он не обещает отсутствия
native chunk-пакетов и не меняет план/потоки/ограничения генерации DH.

## Проверка

Графический сценарий проверяет сохранение уходящего меша после 12 секунд без
native image data, отказ пустой записи в покрытии DH, depth/LOD GPU-проходы,
обе стороны, перестановку деревьев, resource reload и освобождение после ухода.
В нём отмечены 1131 построение и 1121 повторное использование маски. Это
проверка механизма, не сравнение FPS с пользовательской машиной.
