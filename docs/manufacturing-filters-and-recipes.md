# Станки: фильтр, JEI и KubeJS — alpha.76

Изделие выбирается фильтром результата. В меню исчезли кнопки шестерни/сопла/корпуса/крыльчатки; вместо них есть призрачный слот фильтра. Предмет в нём не расходуется, не попадает в массу корабля и не выпадает при разрушении машины.

- Возьмите предмет курсором и нажмите на слот фильтра: сохранится его образец, сам предмет останется у курсора. ПКМ или Shift-клик очищает фильтр.
- Без JEI и без образца: ЛКМ по слоту с пустым курсором переключает выходы подходящих рецептов. Если вход уже заполнен, предлагаются только рецепты этого входа.
- Можно перетащить предмет из JEI прямо в слот. Это позволяет настроить станок до изготовления первой детали.
- Можно применить готовую деталь или настроенный фильтр Create к самому блоку ПКМ, без открытия меню. Они не расходуются.
- Обычный образец выбирает тип изделия независимо от металла. Обычный/атрибутный фильтры, чёрный список и проверка данных работают через штатную реализацию Create.
- Без фильтра станок автоматически берёт первый подходящий рецепт по идентификатору. Фильтр проверяет выход, а вход и окружение — сам рецепт. При смене фильтра незаконченное производство сбрасывается.

Выбор уже установленных станков alpha.75 переносится в новый фильтр. Запас FE и реальные предметы сохраняются. Незавершённое производство при смене формата рецептов начинается заново.

## JEI

Добавлены категории токарного, фрезерного станка и 3D-принтера. Видны вход с количеством, готовая деталь с характеристиками, базовое время, FE/тик, суммарный расход FE, допустимая среда и время/расход на орбите. Станки зарегистрированы как катализаторы категорий. Детали разных материалов различаются в поиске рецептов; место изготовления не мешает искать обычные рецепты применения детали.

JEI — необязательный мод. Create и KubeJS также не стали обязательными зависимостями.

## Формат рецепта

Рецепты используют обычные `ingredients`, `results`, `processingTime`, как производственные рецепты Create, с дополнительными настройками FE и среды. Сериализатор — `around_planet:machining`.

```json
{
  "type": "around_planet:machining",
  "machine": "lathe",
  "ingredients": [{"tag": "c:storage_blocks/iron", "count": 1}],
  "results": [{
    "id": "around_planet:laval_nozzle",
    "count": 1,
    "components": {
      "around_planet:manufactured_part": {
        "material": "around_planet:iron",
        "stats": {
          "wear_resistance": 0.65,
          "working_temperature": 1200,
          "load_capacity": 0.7,
          "corrosion_resistance": 0.35
        },
        "color": 13225682
      }
    }
  }],
  "processingTime": 160,
  "energy_per_tick": 60,
  "orbital_processing_ticks": 120,
  "environment": "any"
}
```

`machine`: `lathe`, `mill`, `printer`. `ingredients` — ингредиенты NeoForge с необязательным `count` (по умолчанию 1); поддерживаются предметы, теги и составные ингредиенты. Машина имеет один входной стек: все перечисленные ингредиенты должны совпадать с ним, а количества суммируются. Общий расход за операцию — не более 64 предметов.

`results` — один гарантированный выходной стек в стандартном формате Minecraft 1.21.1 с `id`, `count` и `components`. Можно производить и обычные предметы. Для полноценной детали нашего мода нужен компонент `around_planet:manufactured_part`: без свойств деталь не пройдёт требования механического сборщика. Во время производства её `environment` автоматически становится фактическим местом изготовления (`ground`, `moon`, `orbit`); материал и характеристики берутся из результата рецепта.

`processingTime` — 1–72 000 тиков. `energy_per_tick` — 1–200 000, по умолчанию 60. `orbital_processing_ticks` — 0–72 000, по умолчанию 0 (использовать обычное время). `environment` по умолчанию `any`, либо `ground`, `moon`, `orbit`.

Стандартные рецепты теперь явные для каждого материала: например, `around_planet:machining/lathe_precision_gear_iron`. Их входы и выходы доступны JEI/KubeJS. Параметры материалов больше не скрывают вход/выход за вычислением в машине. Для нового материала добавьте свои рецепты с его ингредиентами и свойствами в `components`; профиль `manufacturing_materials` можно дополнительно использовать для образцов и ингредиентов механической сборки. Изменение одного профиля не переписывает явные результаты существующих рецептов.

Старые поля alpha.75 `part`, `input_count`, `output_count`, `processing_ticks` заменены явными входами/выходами и `processingTime`. Стандартные ресурсы уже переведены. Свои датапак-рецепты старого формата следует обновить.

## KubeJS

В мод включена JSON-схема KubeJS с входными и выходными ролями. Она обеспечивает обычные операции добавления, поиска, замены и удаления рецептов. Java-аддон к KubeJS не требуется.

Пример в `kubejs/server_scripts/manufacturing.js`:

```js
ServerEvents.recipes(event => {
  // Удаляем исходный рецепт, чтобы он не конкурировал с новым.
  event.remove({id: 'around_planet:machining/lathe_precision_gear_copper'})

  event.custom({
    type: 'around_planet:machining',
    machine: 'lathe',
    ingredients: [{tag: 'c:storage_blocks/copper'}],
    results: [{
      id: 'around_planet:precision_gear',
      components: {
        'around_planet:manufactured_part': {
          material: 'around_planet:copper',
          stats: {
            wear_resistance: 0.3,
            working_temperature: 600,
            load_capacity: 0.4,
            corrosion_resistance: 0.75
          },
          color: 12745297
        }
      }
    }],
    processingTime: 100,
    energy_per_tick: 60,
    orbital_processing_ticks: 75
  }).id('kubejs:quick_copper_gear')

  // Штатный builder схемы, в том числе для обычных предметов:
  event.recipes.around_planet.machining(
    ['2x minecraft:gold_ingot'],
    ['2x minecraft:clay_ball'],
    'mill',
    100
  ).energyPerTick(40).id('kubejs:example_milling')
})
```

Обычные `event.replaceInput(...)`, `event.replaceOutput(...)` и `event.remove(...)` применяются к загруженным рецептам по их идентификатору или типу, по правилам KubeJS. Для изменения конкретных характеристик детали можно удалить её рецепт и добавить новый результат с изменёнными `components`.

## Проверка

Тестовый набор включает настоящий KubeJS и проверяет добавление через `custom`, builder и его setters, замену входа/выхода существующего рецепта с сохранением количества и удаление. Проверяются также нативный фильтр Create, чёрный список, миграция сохранённого выбора, сохранение FE/прогресса и станок на физической конструкции.

Для воспроизведения серверных KubeJS-проверок с подготовленным набором модов:

```sh
./gradlew -PplanetTests -PplanetManufacturingTests -PplanetKubeTests \
  -PcompatModsDir=build/manufacturing76-kube-mods \
  -PplanetTestRunDir=build/manufacturing76-kube-tests runGameTestServer
```

Тестовый скрипт автоматически копируется из `src/planetTests/fixtures/kubejs`. Он и тестовые рецепты не входят в выпускаемый JAR.

Результат проверки alpha.76: 250 модульных тестов, 103 серверных регрессионных, 12 проверок с настоящим KubeJS и 9 без необязательных модов прошли. В клиенте с JEI 19.76.1.483 и KubeJS 2101.7.2 проверены три категории с видимыми рецептами, реальное перетаскивание через обработчик JEI и изготовление выбранного фильтром результата. API интеграции компилируется против JEI 19.21.2.313.
