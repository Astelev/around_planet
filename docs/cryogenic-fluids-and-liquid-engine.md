# Криогенные жидкости и жидкостный двигатель — alpha.48

Жидкий водород (`around_planet:liquid_hydrogen`) и жидкий кислород (`around_planet:liquid_oxygen`) зарегистрированы самим around_planet. Petrochem не нужен для загрузки мода, хранения этих жидкостей и работы двигателя. Есть вёдра, жидкости в мире и стандартный NeoForge FluidHandler; баки и трубы Create работают через этот интерфейс.

Первый двигатель — `around_planet:liquid_rocket_engine`, в творческой вкладке редстоуна. Два независимых буфера вмещают по 4000 mB. Заполнение возможно вёдрами и трубами. Пустая рука открывает настройку расхода смеси от 0 до 1000 кг/с; значение по умолчанию — 50 кг/с. Редстоун регулирует подачу от 0 до 100%. Ключ поворачивает блок, направление тяги совпадает с креативным двигателем. Используется существующий анимированный выхлоп без потока частиц.

Для базовой водородно-кислородной смеси принято массовое соотношение кислорода к водороду 8:1 по физическим плотностям. Объёмное соотношение отличается: плотности равны 70,85 и 1141 кг/м³. В стандартной модели ведро соответствует 1 м³. Энергия смеси — 120 МДж на килограмм водорода, то есть 13,333 МДж/кг полной смеси. При эффективности 0,65 эффективная скорость истечения составляет около 4163 м/с.

Тяга определяется только расходом массы и скоростью истечения: `F = dm/dt × ve`. Импульс равен `dm × ve`. Нехватка одного компонента одновременно ограничивает расход обоих; без одного из них двигатель не создаёт импульс. Остатки меньше миллибакета сохраняются в NBT, внешние трубы не могут округлить их вверх.

При установленном Pondus используются его масса жидкости на ведро, общий множитель жидкостей и множитель содержимого блока. Существующие записи не перезаписываются. Для отсутствующих записей регистрируются стандартные физические плотности и сухая масса двигателя 200 кг. Глобальный множитель Pondus сохраняет своё действие: при меньшей массе миллибакета тот же заданный расход в кг/с требует большего объёма жидкости. При выключенном учёте содержимого/нулевом весе топливо не создаёт бесплатную тягу.

Pondus получает точную массу наших буферов через отдельный адаптер: стандартный целочисленный FluidHandler не показывает долю mB. Без Pondus эту массу учитывает адаптер Sable. Двойного учёта нет. После сборки выполняется однократный пересчёт массы для восстановления содержимого из NBT; при обычном расходе без Pondus обновляется только массовый вклад блока, без пересборки всего аппарата.

Это первый жидкостный этап. Жидкости сейчас доступны для испытаний через творческий режим/команды. Рецепты промышленного сжижения газов Petrochem, другие топливные пары и твердотопливные колонны в эту версию не входят.

## Проверки

Прошли 194 модульных теста, 64 серверных теста с Pondus 0.15, 64 без него и 26 без необязательных модов. Нативные проверки подтверждают точную начальную массу без двойного учёта, равенство потери массы и массы выхлопа, работу коэффициента 0,01, отсутствие тяги без окислителя и сохранение дробного остатка. Прежние проверки нативной тяги учитывают точность 32-битных скоростей Rapier, заметную при небольших массах Pondus.

Клиентская проверка с Create/Pondus/Sodium/DH/Simple Clouds подтвердила передачу из бака Create, открытие интерфейса, расход топлива и отрисовку выхлопа в орбитальной области. Petrochem в тестовой сборке отсутствовал.
