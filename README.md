# around_planet

Minecraft 1.21.1 / NeoForge 21.1.256, Java 21. Имя и mod ID: `around_planet`.

## Экспериментальный переход запад ↔ восток

Серверный перенос обычных сущностей и игрока между краями Overworld.
Периодическая координата X лежит в `[-boundaryX, boundaryX)`.
Например, при `boundaryX = 256`: `256.75 → -255.25`, `-256.125 → 255.875`.
Высота, Z, направление взгляда и скорость сохраняются при готовом переходе.
Север/юг и генерация не изменяются. Сглаживания рельефа на шве нет.

**По умолчанию выключено.** Установите мод на сервер и клиент и включите в новом
тестовом мире: `<world>/serverconfig/around_planet-server.toml`:

```toml
[eastWest]
enabled = true
boundaryX = 65536
activationDistance = 128
destinationRadius = 2
```

После изменения настроек перезапустите мир. `boundaryX` задаёт координаты обоих краёв: по умолчанию это **−65536 и +65536**,
а полный оборот равен 131072 блокам. Значение должно быть кратно 16, от 128
до 29500000; центр по X — ноль. Для небольшого теста можно выбрать 256.
Старый ключ `widthBlocks` заменён на `boundaryX`: прежняя настройка задавала
полную ширину и ошибочно трактовалась как координата края. При обновлении
укажите нужную координату в новом ключе; по умолчанию это 65536.
Зона активации ограничена четвертью полной ширины мира. При быстром движении она
автоматически расширяется до двух секунд пути, максимум до 1024 блоков. Радиус назначения — 1–4 чанка.

В зоне активации временные билеты заранее загружают противоположный край.
Игрок проверяется сразу после обработки принятого vanilla пакета движения,
без дополнительного ожидания следующего серверного тика. При неготовом или
занятом назначении ожидание остаётся необходимым.
Не более 16 областей назначения одновременно; билеты истекают через 100 тиков
после прекращения обновления. Код перехода не ожидает генерацию синхронно.
Если место назначения ещё не загружено или занято блоками/сущностями, объект
удерживается у исходного края. Отступ за край при таком ожидании может быть потерян.

Штатный world border ограничен только по X, на 8 блоков снаружи линии перехода:
этот запас позволяет пересечь линию до включения коллизии border. Границы по Z,
сохранённые центр и размер vanilla border не меняются. Линия перехода находится
на точном `boundaryX`, а не на внешней стене; 8 блоков — только страховочный
запас коллизии. Красное затемнение экрана от проходного шва отключено.
Предупреждение от более узкого обычного border сохраняется. Более узкий существующий
border сохраняет приоритет — его надо расширить для доступа к линии перехода.

## Изображение противоположного края

При включённом переходе реальные загруженные чанки другой стороны автоматически
отображаются за швом. Копии используют штатную сборку секций Minecraft: модели
блоков, воду, прозрачные слои, свет и цвета биомов. Синяя стена border на шве
скрыта; её страховочная коллизия остаётся прежней.

Поддержаны штатный рендер и Sodium; игровой прогон выполнен с Sodium 0.8.13
для Minecraft 1.21.1 / NeoForge, совместно с DH 3.3.3, Cruising Speed и Sable 2.0.6.
Адаптер Embeddium предусмотрен, но пока не проверен в игре. Iris/Oculus и
шейдерпаки отдельно не проверялись.

Изображение ограничено уже подготовленной областью `destinationRadius` (по
умолчанию несколько чанков). Изменения блоков обновляются снимками примерно раз
в 2 секунды. Передача ограничена двумя снимками за тик на игрока, клиентский
кэш — 192 колонками. Слишком большой снимок (свыше 900 КБ) пропускается с записью
в серверный лог. Для отображения обновите мод на сервере **и** клиенте.

Обычные билеты дальности обзора и отправка настоящей территории за границей
отключены. Служебные соседние чанки для генерации, освещения и физического запаса
не блокируются: жёсткий запрет всех соседей мог бы остановить генерацию края.
Существующие сохранённые чанки за границей не удаляются.

С DH 3.3.3 отключаются запросы генерации целиком за границей и показ внешних LOD.
Секции LOD, пересекающие шов, консервативно скрываются целиком. Их отображение с
противоположной стороны ещё не реализовано. Биомная поверхность Cruising Speed
также маскируется за швом. Визуальные копии не отправляют `ChunkEvent.Load` и не
попадают в базу DH или сохранения мира.

Устройство и ограничения: [docs/seam-rendering.md](docs/seam-rendering.md).

В той же полосе показываются отдельные изображения обычных сущностей: мобов,
игроков, предметов, стоек для брони и транспорта с пассажирами. Состояние
обновляется каждые 4 серверных тика, движение интерполируется. Изображения не
входят в игровой список сущностей: их нельзя ударить, подобрать или столкнуть.
Серверные сущности остаются в единственном экземпляре. На игрока передаются
не более 128 изображений и 512 КиБ за обновление; нестандартные протоколы
создания модовых сущностей требуют отдельного адаптера.

У лодки после переноса обновляется серверная точка отсчёта проверки движения.
Отложенная коррекция восстанавливает потерянную посадку только после появления
настоящего транспорта и чанка назначения. Последующий выход из лодки отменяет
устаревшую коррекцию, чтобы она не посадила игрока обратно.

## Что ещё не реализовано

Это пока не полностью бесшовная планета. Визуальные копии используются только
для отображения: взаимодействия и коллизии через разрез не перенаправляются.
Нет изображений физических кораблей, переноса дальних LOD и согласования
генерации. При переходе обычная область клиента меняется, поэтому подгрузка
может быть видна. При резком перепаде высот обратный переход по-прежнему может
блокироваться реальными блоками назначения.

Обычный транспорт переносится вместе с пассажирами без их отсоединения.
Физические конструкции Sable не переносятся; распознанные пассажиры Sable
исключены из обычной телепортации, чтобы не отрывать игрока от корабля.
Сущности на поводке тоже исключены. Полный переход кораблей и связанных объектов
будет отдельным этапом. Не используйте эксперимент для полёта кораблей через границу.

Cruising Speed остаётся отдельным модом `cruising`. Его код, конфиги и рендеринг
не копируются в around_planet. Текущее совместное использование ещё не исправляет
скачок измеренной скорости камеры в Cruising Speed при телепортации. Будущие
стыковки описаны в [docs/architecture.md](docs/architecture.md).

## Разработка и проверки

```sh
bash ./gradlew build
bash ./gradlew -PplanetTests runGameTestServer
bash ./gradlew runClient
```

JAR: `build/libs/around_planet-0.3.0.jar`.
`-PcompatModsDir=/absolute/path/to/test-mods` добавляет локальные JAR только в
среду запуска; они не включаются в мод. Серверные и клиентские тестовые классы
также не входят в итоговый JAR. Клиентский smoke-тест запускается с
`-PplanetClientSmoke runClient` и требует отдельного подготовленного мира
`run/saves/around-ew-smoke` с включённым переходом и `boundaryX = 256`.
Для графической проверки добавьте `-PplanetVisualSmoke`: проверяются настоящий
GPU-рендер обоих берегов, вода, обновления блоков, изоляция от игрового кэша и
фильтры DH при его наличии.

`-PplanetEntitySmoke` вместо `-PplanetVisualSmoke` проверяет модели сущностей
через настоящий сетевой канал и GPU, движение, экипировку, пассажиров, удаление
и очистку. Затем выполняется регрессия лодки: потерянная посадка, гребля через
обе границы, продолжение движения и выход по Shift. Все эти проверки изменяют
только отдельный подготовленный тестовый мир.

Разбор предоставленных JAR Immersive Portals и план устранения перезагрузки:
[docs/immersive-portals-analysis.md](docs/immersive-portals-analysis.md).
