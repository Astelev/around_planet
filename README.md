# around_planet

Minecraft 1.21.1 / NeoForge 21.1.256, Java 21. Имя и mod ID: `around_planet`.

С версии **0.4.0** мод настраивает западный/восточный шов через движок
**Immersive Aeronautics 1.1.4**. Рендер другой стороны, обычные сущности,
загрузка чанков и переход игрока выполняются этим движком. around_planet
создаёт нужную пару глобальных порталов и согласует границы со сборкой.

## Установка

На сервере и клиенте нужны одинаковые версии:

- `around_planet-0.4.6.jar`;
- исходный **Immersive-Aeronautics1.1.4-1.21.1-NeoForge.jar**;
- **Create 6.x** (проверено 6.0.10 с вложенными Flywheel/Ponder);
- **Cloth Config 15.0.140**.

Нужен именно форк Aeronautics: обычный Immersive Portals 6.0.7 не содержит
нужных адаптаций. Он заменяется форком, два этих JAR одновременно не устанавливаются.
У форка внутри сохранён номер `6.0.7`; around_planet дополнительно проверяет
наличие его корабельного модуля. Create требуется фактическому коду форка:
его обработчик посадки обращается к классу поезда даже для обычной лодки.
Зависимости не включаются внутрь around_planet JAR.

В исходном Aeronautics приватный `@Overwrite onChunkReadyToSend` несовместим
с модами, открывающими этот метод `ChunkMap`: мир падает с
`cannot reduce visibiliy of PUBLIC target method`. С **0.4.2** ранний Mixin-плагин
around_planet включает `overwrites.conformVisibility` для общего конфига IP.
Mixin сам согласует доступ overwrite с целевым методом до его применения.
**Менять зависимость физически больше не нужно**, исходный JAR используется
и в `libs`, и в установленной игре. Ранее исправленный `apfix1` тоже допустим,
но устанавливается только один экземпляр Aeronautics.

В 0.4.3 добавлена совместимость столкновений Sable и IP. Если портальный расчёт
обходит Sable, его последующий обработчик сохраняет рассчитанные IP/vanilla
флаги, вместо чтения отсутствующего или устаревшего `sable$collisionInfo`.
Это исправляет найденное в логе падение `Ticking entity` при движении овцы
около портала. Правка применяется при загрузке классов, без изменения JAR зависимостей.

Sable нужен для физических конструкций; проверенный набор использует Sable 2.0.6,
Sodium 0.8.13, DH 3.3.3 и Cruising Speed 1.0.0. Перенос физических кораблей
через наши глобальные границы в этой итерации ещё не подключён.

В **0.4.4** добавлен адаптер DH 3.3.3 для наших западного/восточного порталов:
вторая сторона готовится заранее, её готовое дерево LOD сохраняется при переходе
и повторно используется при возвращении. Пересекающие границу LOD-секции
отсекаются точно в шейдере, а не удаляются целиком, оставляя полосу без рельефа.
Основной вид использует штатный рендер DH. Внутри нашего портала рисуется геометрия
LOD с портальной stencil-маской и глубиной, без полноэкранных fog/SSAO/AA-проходов DH.
Из-за этого вид тумана за порталом может отличаться. Iris shader packs и вложенные
порталы этим адаптером пока не поддерживаются; штатная защита DH там сохраняется.
Simple Clouds остаётся несовместимым с текущим портальным рендером.

## Настройка границ

По умолчанию выключено. В отдельном тестовом мире измените
`<world>/serverconfig/around_planet-server.toml` и перезапустите мир:

```toml
[eastWest]
enabled = true
boundaryX = 65536
portalMinY = -2048
portalMaxY = 16384
portalHalfSpanZ = 29999984
chunkPreloadDistanceBlocks = 512
chunkRadius = 16

[compatibility]
dhPortalRendering = true
dhPreviewDistanceBlocks = 512
```

`dhPreviewDistanceBlocks` задаёт начало подготовки другой стороны (32…4096 блоков).
Дополнительное дерево DH потребляет память и время фоновой подготовки; вдали от
шва оно освобождается. `dhPortalRendering = false` отключает второй кэш и его
портальный проход. После изменения настроек нужен перезапуск мира.

`chunkPreloadDistanceBlocks` отдельно управляет настоящими чанками: их радиус
плавно растёт от двух при входе в полосу до `chunkRadius` у плоскости, оставаясь
не выше обычной дистанции игрока. По умолчанию это 512 блоков и максимум 16
чанков. Допустимый радиус 2…32; увеличение нагружает генерацию, память и сеть.
Чужие порталы сохраняют штатные настройки загрузки.
Центр подгрузки находится внутри противоположного края, а не у виртуальной
камеры за канонической границей, поэтому подготовка действительно начинается
на всей заданной дистанции.

В 0.4.5 в нашем проходе убрана оставшаяся 16-блочная зона отсечения DH. Для
списка LOD используется обычная камера с ближней плоскостью 0.05 блока, без
портальной oblique-плоскости. При depth clamp добавлено отдельное вершинное
отсечение у камеры, чтобы не допускать больших полос из геометрии, пересекающей
ближнюю плоскость. Основной проход DH сохраняет свои настройки overdraw.

Дополнительно перед stencil-масками порталов записывается глубина непрозрачных
LOD основного вида. Штатный финальный шейдер DH копирует только цвет; без этого
более далёкий портал мог перекрывать более близкий рельеф. Дополнительный проход
не меняет цвет, использует готовые VBO и пропускается при отсутствии непрозрачных
буферов. Прозрачная вода и различия тумана остаются отдельными ограничениями.

В 0.4.6 портальный проход исключает LOD по маске готовых настоящих чанков.
Секция исключается только внутри дистанции рендера и после компиляции её меша
(или если она пуста); незагруженные/ещё строящиеся секции сохраняют LOD. Проверка
`LevelRenderer.isSectionCompiled` работает и с Sodium. Генератор не вызывается.
Маска ограничена радиусом 32 чанка и использует переиспользуемую 3D R8-текстуру.
Сдвиг вершин DH для TAA в портале отключён: у этого прохода нет temporal resolve,
поэтому сдвиг расходился с пикселями обычных чанков.

- `boundaryX` задаёт обе плоскости: **−65536 и +65536**, полный оборот 131072
  блока. Кратно 16; допустимо 128…29500000. Для короткой проверки выберите 256.
- Порталы занимают высоты `portalMinY`…`portalMaxY`, независимо от строительного
  лимита. Нижняя высота должна быть меньше верхней. Центр плоскости должен быть
  допустимым для движка порталов; неверная конфигурация отключает управляемую пару
  с сообщением в серверном логе.
- По Z каждая плоскость занимает `[-portalHalfSpanZ,+portalHalfSpanZ]`.
  Северная и южная границы не создаются.

Переход параллельный, без поворота и изменения масштаба; смещение равно одному
полному обороту по X. Например, `65536.75 → -65535.25`. Рельеф на краях
генерируется обычно, сглаживания и периодической генерации пока нет.

Vanilla world border не изменяется. Он должен включать обе точки назначения,
иначе Aeronautics отклоняет порталы. Сохраняются его обычные ограничения и
предупреждения; отдельной страховочной стены around_planet больше нет.

## Сохранение и совместимость

Создаются ровно два отдельных глобальных портала с тегами
`around_planet:ew/east` и `around_planet:ew/west`. Они сохраняются в штатном
хранилище Aeronautics. Повторный запуск сохраняет подходящую пару; изменение
геометрии заменяет только её. `enabled=false` удаляет только управляемые порталы.
Чужие порталы не удаляются. Встроенная команда wrapping-zone на четыре стороны
для этой пары не используется.

Подписки Aeronautics на обычные внешние чанки ограничены по X. Одна внешняя
колонка оставлена для готовности соседей и точек назначения движка. Генерационные
зависимости и отдельные принудительные загрузки не переписываются; приватные
координаты Sable исключены из ограничения. Метаданные и сущности обслуживаются
обычным трекером форка. Проверка despawn рядом со швом учитывает периодическую
дистанцию, сохраняя штатные правила peaceful/persistence и события NeoForge.

С DH 3.3.3 сохранены ограничение внешней генерации и скрытие полностью внешних
секций LOD. Пересекающие шов секции сохраняются с точным фрагментным отсечением.
Поверхность Cruising Speed маскируется за канонической границей; её сквозная
отрисовка и скачок истории скорости камеры Cruising Speed отдельно не исправлены.

В форке обнаружена ошибка регистрации закрытия глобальных порталов на каждом
серверном тике. Локальный совместимый mixin предотвращает это закрытие во время
работы сервера; отдельный GameTest воспроизводит ошибку и проверяет исправление.

## Переход с 0.3.x и текущие ограничения

Старые циклы телепортации, подмена рендера чанков, визуальные копии сущностей,
их пакеты и вмешательство в world border удалены. `enabled` и `boundaryX`
сохраняют смысл. `activationDistance` и `destinationRadius` заменены управлением
самого Aeronautics и больше не используются. Обновите мод и зависимости на обеих
сторонах; сохранения мира и базы DH не очищаются. В 0.4.5 полоса подготовки
реальных чанков отдельно настраивается через `chunkPreloadDistanceBlocks` и `chunkRadius`.

В клиентском тесте при настоящем переходе сохраняются объекты `ClientLevel`,
`LevelRenderer` и заранее загруженного чанка назначения. Это снимает прежнюю
обязательную смену кэша; отсутствие любых пересборок или задержек не гарантируется.

Физические корабли пока не переносятся через управляемую глобальную пару:
пассажиры Sable защищены от отдельной телепортации. Не используйте этот этап для
полёта корабля через границу. Самолёты, сохранение скорости корпуса, удалённые
корабли в том же измерении и север/юг с разворотом — следующие интеграции.

## Разработка и проверки

Поместите предоставленный JAR форка в `libs/` под исходным именем либо передайте
путь явно. Maven-координаты именно этого артефакта пока не найдены; обычный IP
с тем же внутренним номером не является заменой.

Gradle напрямую использует указанный исходный JAR. Задача `patchAeronautics`
из 0.4.1 удалена: совместимость доступа теперь обеспечивается при запуске.

```sh
bash ./gradlew -PimmersiveAeronauticsJar=/absolute/path/to/Immersive-Aeronautics1.1.4-1.21.1-NeoForge.jar build
bash ./gradlew -PimmersiveAeronauticsJar=/absolute/path/to/Immersive-Aeronautics1.1.4-1.21.1-NeoForge.jar -PplanetTests runGameTestServer
```

Create 6.0.10 и Cloth Config 15.0.140 разрешаются из публичных Maven-репозиториев.
API DH 3.3.3 берётся из Modrinth Maven только для компиляции; DH остаётся
необязательной зависимостью и не добавляется в обычный runtime автоматически.
`-PcompatModsDir=/absolute/path/to/test-mods` добавляет только тестовые локальные
моды; не кладите туда второй экземпляр зависимостей, уже заданных Gradle.

Клиентский harness: `-PplanetClientSmoke -PquickPlayWorld=around-portals runClient`.
Нужен отдельный подготовленный мир с включёнными плоскостями ±256,
высотами −128…1024 и `portalHalfSpanZ=1024`; harness изменяет его тестовые блоки.
Он проверяет GPU-вид другой стороны, настоящего удалённого моба, оба направления
на Y=640, сохранение кэша, греблю лодки и выход по Shift. Все fixture-классы
исключены из итогового JAR.

GameTest дополнительно открывает `ChunkMap.onChunkReadyToSend` тестовым access
transformer, воспроизводя условие вылета из сборки. Этот transformer в мод не входит.

Клиентский harness с Sable дополнительно проверяет свежую овцу у портала,
отсутствие старых флагов столкновения после обычного движения и сохранение
обычных столкновений с землёй. После проверки транспорта он сохраняет игрока
у границы, чтобы следующий запуск также проверял вход рядом с порталом.

С DH harness ждёт реально загруженных GPU-буферов на другой стороне и проверяет
идентичность подготовленного дерева после перехода, а исходного — после возврата.

JAR: `build/libs/around_planet-0.4.6.jar`.
Подробности: [архитектура](docs/architecture.md), [рендер шва](docs/seam-rendering.md),
[разбор Aeronautics](docs/immersive-aeronautics-analysis.md).
